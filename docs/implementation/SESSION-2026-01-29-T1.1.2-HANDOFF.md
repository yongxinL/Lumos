## Technical Details

### Database Initialization Flow

```
1. app.ready event
   ↓
2. Call initializeDatabase()
   ↓
3. Open SQLite connection at ~/.config/Lumos/lumos.db
   ↓
4. Enable WAL mode + foreign keys
   ↓
5. Create schema_migrations table
   ↓
6. Run pending migrations
   ↓
7. Return Database instance
```

### Schema Versioning

**Migration Tracking:**

```sql
CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  applied_at TEXT NOT NULL
)
```

**Example Entry:**

```
version=1, name=base_schema, applied_at=2026-01-29T16:30:00.000Z
```

### Append-Only Audit Log

**Enforcement via Triggers:**

```sql
CREATE TRIGGER prevent_audit_update
BEFORE UPDATE ON audit_log
BEGIN
  SELECT RAISE(ABORT, 'Audit log records are immutable');
END;

CREATE TRIGGER prevent_audit_delete
BEFORE DELETE ON audit_log
BEGIN
  SELECT RAISE(ABORT, 'Audit log records cannot be deleted');
END;
```

**Valid Operations:**

- INSERT ✅ (append new records)
- SELECT ✅ (query historical data)
- UPDATE ❌ (blocked by trigger)
- DELETE ❌ (blocked by trigger)

**Rollback Support:**

- `rollback_of` column references previous audit_log.id
- Allows logical rollback tracking without mutations

### Query Optimization

**Indexes Created:**

1. `idx_audit_timestamp` - Fast time-range queries
2. `idx_audit_event_type` - Filter by event type
3. `idx_audit_operation` - Find operations by type
4. `idx_audit_outcome` - Success/failure analysis
5. `idx_skills_status` - Find skills by activation status
6. `idx_skills_priority` - Sort by priority (DESC)
7. `idx_proposals_timestamp` - Timeline queries
8. `idx_proposals_operation` - Operation lookup
