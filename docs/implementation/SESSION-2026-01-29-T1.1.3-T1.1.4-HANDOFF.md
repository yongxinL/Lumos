## Technical Implementation Details

### Type Safety Pattern

**Branded Types Prevent ID Mixing:**

```typescript
// ❌ This won't compile - type mismatch
const skillId: UUID = uuid('skill-123');
const policyId: UUID = uuid('policy-456');
policyRepository.findById(skillId); // ❌ Type error!

// ✅ This compiles - types match
const skillId: UUID = uuid('skill-123');
skillRepository.findById(skillId); // ✅ OK
```

**Helper Functions for Safe Conversion:**

```typescript
// Database row to typed entity
const row = selectByIdStmt.get(id);
const skill: Skill = {
  id: uuid(row.id as string), // string → UUID
  created_at: iso8601(row.created_at as string), // string → ISO8601String
  version_hash: versionHash(row.version_hash as string), // string → VersionHash
  // ... other fields
};
```

### Repository Pattern with Prepared Statements

**Statement Caching:**

```typescript
export class SkillRepository {
  // Cached prepared statements (created once in constructor)
  private selectByIdStmt: Statement;
  private selectByStatusStmt: Statement;
  private insertStmt: Statement;
  private updateStatusStmt: Statement;

  constructor(db: Database) {
    // Prepare statements once
    this.selectByIdStmt = db.prepare('SELECT * FROM skills WHERE id = ?');
    this.selectByStatusStmt = db.prepare('SELECT * FROM skills WHERE status = ?');
    // ... prepare other statements
  }

  findById(id: UUID): Skill | null {
    // Reuse prepared statement (fast!)
    const row = this.selectByIdStmt.get(id);
    return row ? this.deserialize(row) : null;
  }
}
```

**Performance Benefits:**

- Statements compiled once, reused many times
- Better query execution performance
- Automatic parameterization prevents SQL injection
